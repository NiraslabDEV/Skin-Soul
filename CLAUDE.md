💡 Recomendações para a Migração:
Migração do HTML para Next.js: O conteúdo do seu index.html deve ser movido para o arquivo page.tsx dentro da pasta app/. Recomendo usar o Tailwind CSS para substituir o <style> interno, o que garantirá uma performance de carregamento muito superior (menos CSS inutilizado).

Lógica de Dados: Os dados que hoje estão no data.js devem ser movidos para o banco de dados Postgres no Railway. Isso permitirá que você altere preços ou adicione serviços sem precisar fazer um novo deploy do código.

Substituição do LocalStorage: No protótipo, os agendamentos são salvos no navegador (localStorage). Ao subir para o Railway, o Claude deve configurar o Prisma ou Drizzle para salvar esses dados permanentemente no Postgres.

Performance:

Utilize o componente next/image para as imagens, garantindo que elas sejam servidas no formato WebP e redimensionadas automaticamente.

As fontes (Cormorant e Inter) devem ser configuradas via next/font, o que elimina o tempo de espera de conexão com os servidores do Google Fonts.

Este arquivo CLAUDE.md servirá como o manual de instruções definitivo para que qualquer IA ou desenvolvedor siga exatamente o seu padrão visual e técnico.

# Skin & Soul - Diretrizes de Desenvolvimento (CLAUDE.md)

Este documento define as regras estritas para a migração e evolução do projeto **Skin & Soul** do protótipo estático para uma aplicação web de alta performance.

## 🎯 Objetivo
Transformar o protótipo HTML/JS atual em uma aplicação robusta utilizando a stack tecnológica definida, mantendo a fidelidade visual e a experiência do usuário, mas elevando a performance e a escalabilidade.

## 🛠 Stack Tecnológica
- **Framework:** Next.js (App Router)
- **Estilização:** Tailwind CSS (para máxima performance e purga de estilos não usados)
- **Banco de Dados:** PostgreSQL (hospedado no Railway)
- **ORM:** Prisma ou Drizzle
- **Deploy:** Railway
- **Repositório:** `https://github.com/NiraslabDEV/Skin-Soul`

## 📏 Regras de Fidelidade ao Protótipo
- **Design System:** Seguir rigorosamente as cores definidas no `:root` do arquivo `index.html` original (Emerald, Sage, Ivory, etc.).
- **Tipografia:** Manter a combinação de 'Cormorant Garamond' (Serif) para títulos e 'Inter' (Sans) para corpo de texto.
- **Componentização:** O código original deve ser decomposto em componentes React/Next.js, mas a estrutura de DOM e as classes de animação (`reveal`) devem ser preservadas ou adaptadas para Framer Motion/Tailwind Animate.
- **Lógica de Dados:** Utilizar os objetos de serviço e pacotes definidos no `data.js` como base para o esquema do banco de dados.

## 🚀 Otimização de Performance
1. **Server-Side Rendering (SSR):** Utilizar Server Components para renderizar a lista de serviços e o conteúdo estático, reduzindo o bundle JS no cliente.
2. **Image Optimization:** Usar `next/image` para todos os assets visuais.
3. **Fontes:** Utilizar `next/font` para carregar as Google Fonts localmente e evitar layout shift.
4. **API Routes:** Migrar a lógica de agendamento (atualmente no `dashboard.js` e `app.js`) para Server Actions ou API Routes do Next.js integradas ao Postgres.
5. **Caching:** Implementar revalidação de dados para o catálogo de serviços.

## 🗄️ Estrutura do Banco de Dados (Postgres)
- **Tabela `Services`:** Mapear campos de `data.js` (id, cat, name, price, duration, includes).
- **Tabela `Appointments`:** Migrar a estrutura do `APPT_KEY` do localStorage para uma tabela real (id, name, phone, date, time, status, notes).

## 📋 Fluxo de Trabalho
1. **Init:** Configurar o projeto Next.js no repositório indicado.
2. **Migration:** Copiar o CSS do protótipo para o Tailwind ou CSS Modules.
3. **Database:** Configurar o Prisma/Drizzle e conectar ao Postgres do Railway.
4. **Features:**
    - Landing page (Baseada no `index.html`).
    - Sistema de reserva via WhatsApp (Baseado no `app.js`).
    - Dashboard Administrativo (Baseado no `dashboard.html`).
5. **CI/CD:** Configurar o Railway para deploy automático a partir da branch `main`.
